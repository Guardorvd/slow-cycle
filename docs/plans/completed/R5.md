Decisions:

- **RegionRouteGraph is the R5 RouteNetworkPlan.** RouteCorridor is a versioned per-edge view returned by the graph (`slow_cycle.route_corridor/1`). No extra container class.
- **The planner composes its R4/R3 views itself** from the three upstream inputs (EnvironmentContext precedent: no unrelated caller-supplied surfaces/fields). This guarantees identity; the cost is a second, cheap R4 construction in diagnostic tools.
- **The planning raster is plan-local intermediate data**, released after `plan()` returns. It is not a cache, not stored in the graph and not shared.
- Dependency is one-way: R1–R4 → R5 → diagnostics. Nothing upstream reads routes; R4 never receives road/route feedback.
- Single owner: RoutePlanner is the only producer of RegionRouteGraph; the graph owns its immutable data; the preview/map tools only read.

## 4. RegionRouteGraph data model

Schema `slow_cycle.region_route_graph/1`. Storage is integer and region-local (cm, permille, milli-units, enums), like R1/R3, so canonical text and signature are exact. World position = region origin + local.

**Scalars:** region signature, hydrology signature, rideability-field signature, route seed, origin x/z (m), frame symmetry, planning spacing (32 m), versioned `MODEL` string.

**Nodes** (`id, kind, x_cm, z_cm, elevation_cm, anchor_id, justification`):

- `GATEWAY` — degree 1, region entry/exit at a valley end (`REGION_GATEWAY`); R21 continuation, not a dead-end.
- `JUNCTION` — degree 3–4; where routes fork/merge. No degree-2 nodes exist (a route never changes class mid-edge).
- `TERMINUS` — degree 1, a justified dead-end; `justification` ∈ {PASS, SHOULDER, LAKE_SHORE, UPLAND_BASIN, SIDE_VALLEY_HEAD} with its anchor id. Unjustified terminus is invalid.

**Edges** (`id, a, b, route_id, class, length_cm, climb_cm, descent_cm, reasons, crossings[], anchors_passed[]` + corridor arrays): one undirected corridor between two nodes, stations ordered a→b. Corridor arrays (equal length ≥ 2, ~32 m spacing, first/last station at the node positions): `x_cm, z_cm, elevation_cm, grade_permille` (signed a→b), `cross_permille` (cut/fill proxy), `half_left_cm, half_right_cm, cost_milli, biome` (dominant), `flags` (NEAR_WATER, CROSSING, DEVELOPMENT_REQUIRED, STEEP_PINCH, WET, OPEN, DENSE_COVER, JUNCTION_ZONE).

**Crossings** (`station, water_kind MAJOR_RIVER|TRIBUTARY|CREEK, channel_id, x_cm, z_cm, width_cm, depth_cm, angle_deg, hint FORD|SMALL_BRIDGE|BRIDGE`): a required crossing opportunity for R6/R12/R13, not an object.

**Routes** (`id, class, purpose, edge_ids, start_node, end_node, anchor_ids, score_milli, reasons`): the logical journey grouping. Purposes: `BACKBONE`, `LOOP_ALTERNATIVE`, `SHORTCUT`, `CROSS_CONNECTION`, `JUSTIFIED_SPUR`.

**Loops** (`id, fork_node, merge_node, branch_edge_ids, reference_edge_ids, branch_length_cm, reference_length_cm`): explicit independent cycles created by construction. Fork/merge are roles relative to the reference route's orientation (backbone: upstream gateway → downstream gateway); the undirected junction is both, depending on travel direction.

**Anchors** (`id, kind, x_cm, z_cm, elevation_cm, source, status USED|UNUSED|REJECTED, reason_code`).

**Reasons** (edge/route bitmask, derived deterministically, §9): FOLLOWS_RIVER, CLIMBS_TO_BENCH, REACHES_PASS, ENTERS_SIDE_VALLEY, HIGH_TRAVERSE, VISITS_MEADOW, LAKE_SHORE, AUTUMN_WOODS, FOREST_OPEN_TRANSITION, DESCENDS_TO_WATER, RIVER_CROSSING, CREEK_CROSSING, SCENIC_ALTERNATIVE, SHORTCUT, CONNECTS_LOOPS.

**Diagnostics** (deterministic, separately hashed, outside the network signature): rejected candidates (bounded, ≤ 96: purpose, class, anchor, reason code, decimated polyline, score breakdown), degrade codes, anchor rejections, raster summary, per-class counts/lengths. Timings are never in any signature; tools measure them.

**Queries:** `get_route_node_count/get_route_node(i)`, `get_edge_count/get_edge(i)`, `get_corridor(i)` (RouteCorridor dictionary incl. world-space float positions), `edges_at(node)`, `get_route(i)`, `get_loop(i)`, `get_anchor(i)`, `get_diagnostics()`, `canonical_text()`, `signature()`, `validate()`. Accessors return deep copies. Signature = SHA-256 of schema + input signatures + MODEL + canonical network text.

**RouteCorridor meaning for R6:** the reference line is *not* a spline or centreline. R6 may place the road anywhere inside the band (per-station left/right half-widths), entering/leaving through the junction zones (96 m radius). `DEVELOPMENT_REQUIRED` says natural grade exceeds the class preference and the road needs extra length (traversing/switchbacks) inside a widened band — R5 does not design that geometry.

## 5. Inputs, failure behaviour and efficient R4 sampling

`RoutePlanner.plan(region_plan, terrain_field, hydrology_plan) → {is_valid, graph, reason_code, detail, diagnostics}`. Inputs are type/identity-checked exactly like EnvironmentContext (region signature, terrain bounds, hydrology region signature/origin). The planner then creates EnvironmentContext → BiomeField → RideabilityField and HydrologyField → HydrologySurface from the same inputs.

Failures (no product, no fallback straight route): `ERR_ROUTE_INPUT_MISSING`, `ERR_ROUTE_INPUT_INVALID`, `ERR_ROUTE_INPUT_MISMATCH`, `ERR_ROUTE_DEPENDENCY` (original R3/R4 reason in detail), `ERR_ROUTE_NO_GATEWAY`, `ERR_ROUTE_NO_BACKBONE`, `ERR_ROUTE_GRAPH_INVALID` (validator reasons in detail — a planner defect, never hidden).

Degrade codes (valid graph, explicit): `DEGRADED_NO_LOOP`, `DEGRADED_FEW_LOOPS` (<2), `DEGRADED_FEW_SECONDARY` (<2), `DEGRADED_FEW_SINGLETRACK` (<2), `DEGRADED_NO_TECHNICAL_SITE`, `DEGRADED_NO_CROSS_CONNECTION`, `DEGRADED_ANCHOR_KIND_UNREACHED:<kind>`. They make honest geography limits visible; they are evaluated in §12, not silently tolerated.

### Planning raster (RoutePlanningRaster)

- 129 × 129 nodes at 32 m, local (32 i, 32 j), aligned with the hydrology drainage lattice (body cells exact per node) and with even TerrainField 16 m indices.
- Per node, packed arrays: natural height and gradient (HydrologySurface), slope, R4 cost/class/blocked/reason flags, exact water flag/depth, woody cover, moisture, dominant biome + meadow weight, valley-floor weight, relative elevation, capped water distance, body id, channel mask (node within channel half-width + 32 m of a channel segment), region-edge distance.
- Construction: one pass over even lattice rows using the public lattice paths `RideabilityField.sample_combined_lattice(i0, j, 257, 1)` and `HydrologySurface.sample_lattice` at the same rows, keeping even columns. R3/R4 point/lattice parity makes these bit-identical to point queries (asserted on a sample). M1 benchmarks this against 16,641 direct point queries and keeps the faster; no contract difference. Expected ~6–15 s.
- No full-proximity calls, no 16 m full-field evaluation, no per-search resampling, no persistent/global cache, no threads.

### Exact checks only where they matter

- **Crossings:** additive `HydrologyField.sample_segment_crossings(x0, z0, x1, z1)` → `{is_valid, reason_code, crossings[], body_ids[]}`. Uses existing segment storage and 128 m search buckets along the segment, exact segment–segment intersection, width/surface/bed interpolated at the hit, crossing angle; ordered by (t, channel id). Segment length ≤ 256 m else `ERR_HYDRO_SEGMENT_LENGTH`; coordinate validation as existing queries. During search it is called only for moves touching channel-masked nodes, memoised per (node, direction) inside one plan run.
- **Corridor certification:** exact `RideabilityField.sample_combined` every ≤ 8 m along accepted corridor reference lines only (a few thousand calls, ~3–5 s).

## 6. Geographic anchors (RouteAnchorFinder)

Anchors are planning reasons for a route to go somewhere. They are not landmarks, vistas, destinations or gameplay objects, and no visibility is computed. Descriptor data only seeds a local search; acceptance always depends on the sampled world.

| Kind | Discovery (hint → verification) | Typical use / Alpha value |
|---|---|---|
| GATEWAY | Major-river boundary exits at both valley ends; per bank, the best dry, non-blocked boundary node within ±384 m with valley-floor weight ≥ 0.5 | Backbone terminals |
| RIVER_REACH | Major-river stations every 512 m, per bank; dry OPEN/RIDEABLE node 40–160 m from water | Valley alternatives, "follows river" / 0.5 |
| SIDE_VALLEY_MOUTH | Tributary (order ≥ 2 or ≥ 600 m long) mouth; dry node beside the confluence | Side-valley entry / 0.5 |
| SIDE_VALLEY_HEAD | Highest tributary point ≥ 500 m above the mouth where slope ≤ 0.25 | Side-valley loops; may justify a terminus / 0.8 |
| PASS | Bottleneck (minimax-height) path between adjacent crest summits on raster heights; the pass is that path's highest node. Descriptor SADDLE only bounds the window; offset recorded (R1-D2) | Crossings of the range, high loops, justified terminus / 1.2 |
| SHOULDER | Highest non-blocked node with slope ≤ 0.35 within 150 m of a spur midpoint | High points, technical starts, justified terminus / 0.9 |
| SPUR_NOSE | Spur lower end above the valley wall | Technical descent end / 0.4 |
| BENCH | Descriptor bench side/u-range → longest run of nodes with slope ≤ 0.15 and relative elevation 0.1–0.5 on that wall; else `BENCH_NOT_FOUND` | "Climb onto a bench" loops / 0.8 |
| UPLAND_BASIN | Descriptor basin → flattest dry node in its radius with meadow affinity | High meadow, justified terminus / 1.0 |
| MEADOW | 8-connected components of dry OPEN meadow-dominant nodes ≥ 12 nodes; the most interior node; ≤ 6 largest | Forest/open variety / 0.6 |
| LAKE_SHORE | Bodies ≥ 4 cells → best dry non-blocked shore node within 64 m | Water destination, justified terminus / 0.8 |
| AUTUMN_POCKET | BiomeField descriptor pocket (if present) → lowest-cost autumn-dominant node | Biome variety / 0.7 |

Stable ids follow (kind order, source order). Rejections are kept with reasons: `ANCHOR_BLOCKED`, `ANCHOR_WATER`, `ANCHOR_EDGE_MARGIN` (< 64 m from region edge), `PASS_NOT_TOPOGRAPHIC`, `BENCH_NOT_FOUND`, `ANCHOR_DUPLICATE` (within 160 m of a stronger anchor). Values and tolerances are versioned Alpha parameters.

## 7. Traversal cost model (RouteSearch)

Search graph: raster nodes, 16-neighbour moves (32 / 45.3 / 71.6 m), plus **crossing jumps**: from a dry node across ≤ 3 consecutive water nodes (≤ 96 m) to the first dry, non-blocked node, along one of the 16 directions. Water and body nodes are never standing nodes; body water is never crossed in Alpha.

Move cost (all factors ≥ 1, so the heuristic stays admissible):

```text
cost = L · G^γ · A(g_along) · (1 + w_x · g_cross) · V · S  +  X
```

- `G` = mean R4 cost of the two endpoints and the bilinear midpoint (natural ground resistance); `γ` = class ground weight.
- `g_along = |Δh| / L` from raster heights. `A = 1 + (g/g_pref)²` up to `g_max`. Above `g_max`, a class that allows development is costed as if lengthened to `Δh / g_pref × 1.35` and flagged DEVELOPMENT_REQUIRED; otherwise forbidden. Slope therefore appears twice: as ground roughness (R4) and as route geometry (R5) — intentional and documented.
- `g_cross` = gradient component perpendicular to the move: the cut/fill estimate.
- `V` (backbone only) = `1 + 0.6 · (1 − valley_floor_weight)`: the backbone is the valley road.
- `S` = separation: `1 + k_sep · (1 − smooth(0, R_sep, D))`, D = distance to the existing network (chamfer raster, updated after each acceptance), waived within 96 m of the search's own source/targets so routes can attach. Alpha: R_sep 160 m, k_sep 3.
- `X` = crossing cost: class base + span term + oblique-angle penalty (angles < 60°), limited by a network bridge budget.
- Forbidden: blocked nodes, standing on water, body crossings, nodes < 64 m from the region edge (except gateway approach), crossings the class does not allow.

| Profile (Alpha starting values) | BACKBONE | SECONDARY | SINGLETRACK | TECHNICAL |
|---|---|---|---|---|
| `g_pref` / `g_max` | 0.06 / 0.10 | 0.09 / 0.15 | 0.14 / 0.22 | 0.22 / 0.38 |
| Development above `g_max` | yes (wide band) | yes | yes (tight) | no |
| Ground weight `γ` | 1.3 | 1.0 | 0.8 | 0.5 (DIFFICULT acceptable) |
| Cut/fill weight `w_x` | 3.0 | 2.0 | 1.0 | 0.5 |
| Crossings allowed | FORD, SMALL_BRIDGE, BRIDGE | all | FORD, SMALL_BRIDGE | FORD |
| Corridor base half-width | 40 m | 50 m | 35 m | 25 m |

Algorithms: A* (heuristic = Euclidean distance × 1, admissible) for point-to-point; multi-target Dijkstra for attach searches. Binary heap keyed (cost, node index, direction) for deterministic tie-breaking; optional bounding box (endpoints + 1 km) if M1 measurement needs it. Up/down travel is symmetric in Alpha (DEBT). Kernels are static functions over packed arrays, so controlled-array tests exercise the real production code.

## 8. Building a worthwhile network (RoutePlanner + RouteJourneyScoring)

**Principle.** *Geometry comes from traversal cost; existence and placement come from journey purpose.* Journey interest never subsidises an implausible line (no negative costs or bonuses inside a search). It decides which purposeful candidates are generated and which are kept. Every accepted route can state why it exists.

### Stage 0 — Backbone

Gateways at both valley ends, per bank: up to four gateway pairs. A* with the BACKBONE profile for each pair; choose the lowest cost including bridge costs; pairs within 3 % are broken by the route seed. The backbone is the one route where minimum cost is right: it is the calm, legible valley road. It may cross the river where narrows force it. Interest comes from the rest of the network. No feasible backbone → `ERR_ROUTE_NO_BACKBONE`.

### Candidate generators (evaluated against the current network)

1. **Loop through an anchor.** S1: multi-target Dijkstra from the anchor to the attach set (network nodes ≥ 200 m along-network from existing junctions, or existing junctions with degree < 4, never within 200 m of a gateway) → attach t1, path p1. S2: same search, excluding attach nodes within 800 m along-network of t1 and with p1 added to the separation field → t2, p2. Candidate = p1⁻¹ · p2, forking at one attach and merging at the other. If S2 fails or costs > 2.5 × S1, the candidate becomes a `JUSTIFIED_SPUR` only for terminus-eligible anchor kinds; otherwise `REJECT_NO_SECOND_ATTACH`. One mechanism produces opposite-bank valley alternatives (via river crossings), side-valley circuits (up one side valley, over a spur or bench, down the next), bench loops and pass loops.
2. **Shortcut / descent.** Network station pairs (every ~200 m) whose along-network distance is ≥ 1.8 × direct distance and with relief ≥ 40 m: direct search with the round's class; keep the best 12 pairs by detour × relief before searching.
3. **Technical line.** Shortcut pairs with relief ≥ 60 m where a SHOULDER, SPUR_NOSE or PASS lies within 150 m of the direct line: steep, direct descents down a spur crest. They always parallel an easier connection.
4. **Cross-connection.** Pairs of non-backbone routes whose closest approach is ≤ 450 m but whose along-network distance is ≥ 3 × that approach and ≥ 1.2 km: connector search (SECONDARY or SINGLETRACK, whichever profile is cheaper on that terrain). This turns independent loops off the backbone into a network.

### Rounds and quotas (greedy, deterministic)

| Round | Class | Generators / eligible anchors | Target – max |
|---|---|---|---|
| 1 | SECONDARY | loop: RIVER_REACH (opposite bank from backbone), BENCH, SIDE_VALLEY_HEAD, UPLAND_BASIN, LAKE_SHORE, MEADOW, AUTUMN_POCKET | 2 – 4 |
| 2 | SINGLETRACK | loop: SHOULDER, BENCH, MEADOW, LAKE_SHORE, SIDE_VALLEY_HEAD, PASS, AUTUMN_POCKET; shortcut/descent | 2 – 4 |
| 3 | TECHNICAL | technical lines; anchor descents | 1 – 2 |
| 4 | cross-connection | route pairs | 1 – 3 |
| 5 | dead-end audit | every TERMINUS justified, else connector attempt, else prune and record | — |

In each round: generate all candidates, score, accept the best with JVS ≥ class floor, update network + separation raster, regenerate, repeat until the max or no candidate qualifies. Anchors within 120 m of the network count as visited. Network length cap 34 km (Alpha); network bridge budget 4. Missing targets produce degrade codes, never forced low-value routes.

### Journey Value Score (JVS) — the Alpha journey-interest concept

```text
JVS = 1.0 · novelty_km                     length > 150 m from the pre-existing network
    + Σ anchor_value(kind) · (1.0 new kind for network | 0.5 repeat)   anchors within 80 m, once each
    + 0.5 · min(relief_gain / 0.25·relief, 1)   climbs onto benches/shoulders/passes
    + 0.3 · min(biome_transitions, 3)        forest ↔ open ↔ riparian changes
    + 0.8 · contrast                          character difference from the parallel network path
    − 0.6 · max(0, cost_per_km / class_norm − 1)
    − 0.8 · max(0, detour_ratio − class_detour_max)
```

`contrast` = mean absolute difference of normalised character vectors (mean/max relative elevation, fraction woody, fraction open meadow, fraction within 60 m of water, mean |grade|, crossings per km) between the candidate and the network path between its attach points. This favours exposing new ground, using real terrain features, giving loops a different character than their reference, and avoids pointless or tortuous additions. Weights/floors are versioned Alpha parameters tuned on development seeds only (§12).

Hard rejects (recorded with polyline for the map): `REJECT_DUPLICATE` (> 20 % of the reference line within 64 m of the network outside junction zones), `REJECT_JUNCTION_ANGLE` (< 30° at 96 m), `REJECT_JUNCTION_SPACING` (< 200 m), `REJECT_LOOP_TOO_SHORT` (< 1.2 km), `REJECT_DETOUR`, `REJECT_LOW_VALUE`, `REJECT_BUDGET`, `REJECT_UNCERTIFIED_BARRIER`, `REJECT_NO_SECOND_ATTACH`, `REJECT_UNJUSTIFIED_SPUR`.

**Determinism and seed use.** Enumeration is in stable id order; ties break by id. The registered `route` seed is used only where options are genuinely near-equal: backbone pairs within 3 %, top candidates within 5 % JVS (draw from route seed + round + candidate ids). Diversity therefore comes from geography, hydrology, environment and anchor availability, not random roads. No branch keyed to any seed.

**Against shortest-path monotony and duplicates.** No artificial wiggle rules. Shape emerges from purposes visiting anchors, the grade vs cut/fill trade-off, crossings and separation. Duplicates are prevented by the separation term, duplicate rejection, corridor clipping and validator checks. Sinuosity and heading change per km are diagnostic observations only.

**Navigation legibility.** Junction angle ≥ 30°, junction spacing ≥ 200 m, degree ≤ 4, no junction on water/barrier, one continuous backbone, calmer classes never depend on harder ones (§10).

## 9. Graph assembly and corridors (RouteCorridorBuilder)

- **Assembly:** accepted node paths; attach points become JUNCTIONs; routes split into edges at junctions; GATEWAY/TERMINUS ends. Junction stores incident edges ordered by bearing (clockwise from north = −Z) and its through pair (highest classes).
- **Reference line:** Douglas–Peucker (ε 12 m) over node centres, keeping junction and crossing points; stations every 32 m (last shorter), integer cm.
- **Station attributes:** raster bilinear for continuous values, nearest for categories; grade from station heights; cut/fill from cross gradient.
- **Corridor width:** class base half-width; × 2 (cap 120 m) along DEVELOPMENT_REQUIRED runs; clipped by a lateral raster scan (16 m steps) at barriers, water/body nodes, the region margin and half the distance to any other edge outside junction zones. Minimum 8 m per side, else reject. Corridors therefore never overlap outside junction zones.
- **Certification:** exact point samples every ≤ 8 m. DEEP_WATER outside a recorded crossing → REPLAN with the offending node marked impassable for that run (≤ 2 replans, then `REJECT_UNCERTIFIED_BARRIER`). EXCESSIVE_SLOPE → STEEP_PINCH flag; rejected if a pinch has < 16 m lateral room on both sides. Barriers are never smoothed away.
- **Crossing records** from `sample_segment_crossings` on each reference segment. Hint: creek ≤ 3 m wide, depth < 0.35 m → FORD; ≤ 8 m → SMALL_BRIDGE (FORD allowed if shallow); major river or depth ≥ 0.35 m → BRIDGE.
- **Reasons** derived from anchors passed, ≥ 40 % of stations within 120 m of the major river (FOLLOWS_RIVER), biome run transitions, net descent toward water, crossings and purpose.

## 10. Validator and durable invariants

`RegionRouteGraph.validate()` returns `{is_valid, reason_codes}`; the planner calls it before returning and fails with `ERR_ROUTE_GRAPH_INVALID` otherwise.

| Reason | Invariant |
|---|---|
| `ERR_GRAPH_SCHEMA`, `ERR_GRAPH_ID`, `ERR_GRAPH_REFERENCE`, `ERR_GRAPH_ANCHOR_REFERENCE` | Keys/types, dense ids equal indices, valid node/edge/route/anchor references |
| `ERR_GRAPH_SELF_LOOP`, `ERR_GRAPH_ORPHAN` | No edge a = b; no isolated node; every edge in exactly one route |
| `ERR_GRAPH_NODE_DEGREE` | GATEWAY/TERMINUS degree 1, JUNCTION 3–4, no degree 2 |
| `ERR_GRAPH_DISCONNECTED` | One connected component |
| `ERR_GRAPH_BACKBONE` | BACKBONE edges form exactly one simple path between two GATEWAYs at opposite valley ends |
| `ERR_GRAPH_HIERARCHY` | For each class C, the subgraph of classes ≥ C (in BACKBONE > SECONDARY > SINGLETRACK > TECHNICAL order) is connected |
| `ERR_GRAPH_TECHNICAL_REQUIRED` | Technical edges end at junctions; removing all TECHNICAL edges keeps the network connected |
| `ERR_GRAPH_BACKTRACK` | Every graph bridge edge is on the backbone path or leads only to justified termini (no mandatory backtracking) |
| `ERR_GRAPH_UNJUSTIFIED_DEAD_END` | Every TERMINUS has an eligible justification and existing anchor |
| `ERR_GRAPH_LOOP_RECORD` | Each loop record forms a cycle; branch ≥ 1.2 km; recorded loops ≤ cyclomatic number |
| `ERR_GRAPH_JUNCTION_ANGLE`, `ERR_GRAPH_JUNCTION_SPACING` | ≥ 30° at 96 m; junction–junction edges ≥ 200 m |
| `ERR_GRAPH_CORRIDOR` | Finite values, arrays equal length ≥ 2, spacing ≤ 32 m, endpoints at nodes, half-widths 8–120 m, inside region margin |
| `ERR_GRAPH_DUPLICATE`, `ERR_GRAPH_CORRIDOR_OVERLAP` | ≤ 20 % overlap within 64 m outside junction zones; no corridor overlap outside junction zones |
| `ERR_GRAPH_CROSSING_RECORD` | Valid station index, kind/hint compatible with route class |

Hydrology-dependent audit (RouteCorridorBuilder, run by planner and tests): every reference segment crossing a channel has a record (`ERR_ROUTE_CROSSING_MISSING`) and every record matches a real crossing (`ERR_ROUTE_CROSSING_PHANTOM`).
