**Reference audit** (closure proof): search `class_name`, `res://` path, `preload/load` strings across `*.gd/*.tscn/*.tres/*.gdshader/project.godot` (incl. autoloads) for each changed path, transitively to the main scene. Record command + result. **Inconclusive ⇒ treat as reached.**

### 4.2 Evidence reuse (small rule)

Evidence from run R on source S may count for candidate C only if: (a) every file in the check's closure (entry script, reached production files, scenes/resources/settings) is byte-identical S↔C, or the S→C diff is shown unreachable by §4.1 audit; (b) engine binary/version, launch args, seeds/config are identical (Vulkan/perf also same driver/GPU); (c) R is complete with raw logs retained and its verdict carried as-is — a reused FAIL stays FAIL; (d) the report labels it `REUSED <run id> <closure proof>`. Reuse never upgrades an E-level and never certifies a check that was never run. Precedent: R5 freeze 2→3 reuse accepted by VERIFY.

### 4.3 Escalation triggers (scope expands immediately)

Public contract/schema/signature or existing seed purpose changed → all consumer suites. Any FAIL, unexpected error/leak, nondeterminism or unexplained timeout → rerun the failing check plus its closure at the next level. Inconclusive audit → reached. Engine/driver change → no Vulkan/perf reuse. Holdout failure → fix at cause, failing seeds become disclosed regression rows. Human complaint or reviewer doubt → targeted investigation. A demonstrated safety/correctness problem overrides any budget.

### 4.4 Campaign hygiene

- **Holdout:** never during tuning. Run once per frozen candidate. After an L2 fix: rerun the failing rows, the new suite and one deterministic quarter of the holdout; a full holdout rerun is required when the fix changes a contract, acceptance rule or reject reason, or the quarter shows a new failure. Report exactly which holdout coverage belongs to the final identity.
- **Fixtures:** for L0 (and L1 when the upstream closure is unchanged) a serialized real-region upstream snapshot is allowed if it records upstream closure digest + seed/region/config and is invalid on any upstream change. Optional, per ExecPlan whitelist; L2 always builds the declared real cases live (E2).
- **Visual pack:** L2 human pack ≤ 12 images total (maps/profiles/Vulkan) chosen against named human questions, plus failure examples; raw diagnostics stay in the evidence root uncurated.
- **Performance:** without a §4.1 perf trigger, L2 records one isolated timed run per declared case and one create/release object-count check; 3-repeat benchmarks and 10-cycle soak belong to perf-triggered changes and L3.
- **Concurrency:** ≤ 4 concurrent Godot processes, ≤ 1 Vulkan; timings only from isolated runs; record concurrency in reports.
- **Documents:** phase ExecPlan target ≤ 15 KB, small fix ≤ 3 KB; N/A one line. Completed records keep verdicts, identities, findings, DEBT and ledger; full reports stay in the evidence root by digest (≤ 1 page summary each in the record).
- **Docs-only closeout:** edits confined to Markdown records/state docs with the verified code manifest unchanged need link/scope/hash checks only — no fresh VERIFY/REVIEW. Governance files (AGENTS/skills/PLANS) are not "closeout docs".

### 4.5 Independence

VERIFY (independent context): audits identities, scope and all stored raw evidence; **re-executes** E0 import + the primary new/changed suite once on the frozen identity, plus any check whose stored evidence is missing, inconsistent or doubtful; does not rerun batteries/holdout/Vulkan/benchmark otherwise. REVIEW (fresh context): reads plan + diff + VERIFY report risk-targeted; **no campaign rerun**; at most one focused probe to settle a specific doubtful claim, else returns the question to the verifier. Fixes: fresh VERIFY/REVIEW of the **changed diff's impact set**, not the whole campaign.
