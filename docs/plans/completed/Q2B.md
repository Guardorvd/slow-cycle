## 5. Ranked root-cause hypotheses

**H1 — exit-window audio playback release race (most likely, unproven).**
- **Claim:** The live playbacks of the looping autoplay players, and the procedural streams they reference, are released asynchronously by the AudioServer after teardown. If the process reaches engine shutdown first, they survive to `ObjectDB::cleanup`.
- **Supporting evidence:**
  - The count is fixed per scene.
  - It does not depend on world progress or the number of scenes built.
  - The rate falls as quit latency after the last teardown grows.
  - Leaking and clean runs have identical workloads.
- **Contradicting or open evidence:**
  - The engine internals are unverified.
  - Route warned once despite ~2 physics frames of settle.
  - The `8` is not directly observed.
- **Falsified if any of these hold:**
  1. Verbose classes are not audio playback/stream types.
  2. Same-process ID provenance assigns them to another owner.
  3. AUDIO_REMOVED does not reduce the target signature.
  4. WAIT does not reduce it. That alone weakens only the timing mechanism, not ownership.

**H2 — deferred deletion pending at exit.**
- **Claim:** Nodes `queue_free()`d by `_exit_tree` (audio players) or by despawn/unload (chunks) are still pending at quit.
- **Contradicting evidence:** the SceneTree flushes its delete queue at finalize; parent `free()` destroys children immediately; the count does not track chunk churn.
- **Falsified if:** verbose classes are not Node types with node paths.

**H3 — world-domain retention.**
- **Claim:** RefCounted cycles (`RoadBranch` ↔ `ForkDecisionModel`/bound Callable, `RoadGraph`, path slices) or orphan streamer nodes survive.
- **Contradicting evidence:**
  - A cycle would be deterministic for a deterministic ride, yet only 4/14 warn.
  - The count would scale with forks and instances.
- **Falsified if:** there are no world classes in verbose output, provenance gives no world-owner IDs, and there are no D3 tracked world survivors.

**H4 — other fixed per-scene owners.** These are `SlowCycleLogger` static `WeakRef`/buffers, the camera `FastNoiseLite`, HUD connections and the fader tween.
- **Contradicting evidence:** they would be deterministic, and their counts do not fit.
- **Falsified by:** verbose classes and provenance.

**H5 — engine/.NET runtime finalisation unrelated to project objects.**
- **Falsified if:** leaked objects are project-created by same-process provenance, and AUDIO_REMOVED reduces the target signature.

**Multiple causes** are concluded when distinct signatures exist (§8), or when non-target occurrences persist under the interventions. They are never collapsed into one.

**R1-NB1 (evidence channel, not a cause).**
- **Claim:** the engine closes the `--log-file` logger before `ObjectDB::cleanup`.
- **Checked by:** all verbose `Leaked instance:` lines and WARNINGs being absent from `engine.log` but present on stdout/stderr.
- **Optional corroboration:** read-only citation of the 4.7.2-stable `main/main.cpp` cleanup order.
- **Outcome:** an explanation only. stderr stays authoritative, and no harness change follows.

### 6.3 `target_leak_signature` (amendment 2)

A signature is a semantic record. It is never a number:

```
target_leak_signature = {
  classes:        multiset of engine classes from verbose "Leaked instance:" lines,
  owner_relation: per class, the project owner/role proven by same-process ID provenance
                  (e.g. "<Player>.stream", "<Player>.get_stream_playback()"), or UNATTRIBUTED,
  object_paths:   resource path / node path as printed (empty paths recorded as empty),
  creation_path:  source file:function of creation for the attributed owner,
  teardown_path:  teardown sequence of the run (e.g. scene.free → _exit_tree → quit),
  per_owner_unit: objects per attributed live owner instance,
  nominal_counts: C_target = set of WARNING counts of D1 occurrences matching this signature
}
```

**Derivation** (mechanical, predeclared, frozen before D2):
- Take every D1-P NORMAL verbose occurrence whose `Leaked instance:` count equals its WARNING count.
- Group them by (class multiset, owner_relation pattern).
- Each group with ≥ 1 fully attributed occurrence (every leaked ID matched in the same process) is a signature S_i.
- If exactly one signature exists, it is `target_leak_signature`. If several exist, each S_i is kept separately (multiple-cause path, §8).
- The runner writes `aggregate/target_signature.json` and its sha into the ledger **after ordinal 37 and before ordinal 38 starts**.
- D1-R and D1-V occurrences, which emit no IDs, are compared to S_i by class multiset and paths only (real-path linkage).
- If no D1-P NORMAL occurrence is fully attributed, the observable facts (classes, paths, counts) are reported, no causal claim is made, and Stage D STOPs (§13).

**Non-verbose classification** (D2, applied identically to every arm):
- `TARGET_COMPATIBLE` iff the WARNING count ∈ C_target.
- Otherwise `NON_TARGET:<count>`, kept and evaluated separately.
- **Limitation (stated in every report):** non-verbose runs expose only the count. Membership is inferred from the D1-established semantic mapping, and a different-class leak with a coincidentally equal count cannot be excluded non-verbosely.
- **Mitigations:**
  - the 6 verbose AUDIO_REMOVED runs in D1-P show the classes of any leak under the intervention;
  - for NORMAL and WAIT, a same-run consistency check (count = per_owner_unit × live attributed owners from `Q2B_OWNED playing=true`) is reported as supporting data, not used for acceptance.

## 8. Root-cause acceptance criteria and decision logic

**Statistical contract** (predeclared, amendment 5):
- **Primary test (ownership):** H1: P(target | AUDIO_REMOVED) < P(target | NORMAL). One-sided Fisher exact test on D2-I target-compatible occurrences, α = 0.01.
  - Acceptance requires **all three:** NORMAL ≥ 7/30 target occurrences, AUDIO_REMOVED = 0/30 target occurrences, and one-sided p ≤ 0.01. For reference, 7/30 vs 0/30 gives p ≈ 0.0053.
- **Secondary test (mechanism):** H1: P(target | WAIT) < P(target | NORMAL). One-sided Fisher, α = 0.01. This supports the exit-time cleanup-race mechanism only.
- **Fixed in advance:** sidedness and α. No post-hoc switch to two-sided tests or other thresholds.
- **If several signatures S_i exist:** each S_i is tested separately with α = 0.01 / k (Bonferroni, k = number of signatures). They are never pooled.
- **Reported for every arm:**
  - raw counts: target, non-target by count, none, INFRA;
  - two-sided Clopper–Pearson exact 95% intervals for target and any-warning proportions;
  - for a 0/30 arm, also the one-sided exact 99% upper bound (≈ 0.142);
  - exact p-values.
- **Separation:** D1 verbose and D2-R results appear in separate tables and never enter these tests.

**Criteria:**

| # | Criterion |
|---|---|
| RC1 Identity | ≥ 2 D1-P NORMAL verbose occurrences, each with `Leaked instance:` count = WARNING count and classes recorded. |
| RC2 Local ownership | `target_leak_signature` derived per §6.3 from fully attributed occurrences (same-process IDs only). |
| RC3 Primary causal test | Statistical contract met for the target signature. |
| RC4 Mechanism | Secondary test result reported. A pass adds exit-race support; a fail leaves ownership standing but timing unexplained. |
| RC5 Real-path linkage | ≥ 1 D1-R or D1-V occurrence whose class multiset and paths match the signature. D2-R occurrences are classified and reported. |
| RC6 Target lifecycle retention (D3) | In every one of the 9 cycles (3 runs × 3), `Q2B_SURVIVORS alive = 0` for T-AUDIO, T-WORLD and T-SCENE after teardown + 500 ms settle, with no monotonic growth of survivors across cycles. Global `Q2B_COUNTS` are observational only and never acceptance criteria. Any tracked survivor that persists or grows is reported as **ACCUMULATING_RETENTION** (a separate cause) with its classes. The claim is limited to "no retention of the tracked owners on the exercised path", never "no runtime retention exists". |
| RC7 Completeness | Every D1/D2 non-target occurrence is kept and evaluated. Historical counts are explained by the signature (6), or marked "consistent but not directly observed" (8) unless observed. NB1 is classified. |

**Decision logic** (amendment 6):
- NORMAL reproduces the target signature **and** AUDIO_REMOVED removes it (RC3) → **supports audio ownership causality.**
- WAIT materially suppresses the same signature (RC4) → **additional support for the exit-time cleanup-race mechanism.** WAIT alone never proves correct lifecycle ownership.
- AUDIO_REMOVED does not reduce the target signature → **audio hypothesis not established.**
- Signatures or classes differ across groups, or non-target occurrences appear under AUDIO_REMOVED/WAIT → **possible multiple causes.** They are not collapsed and are evaluated separately.
- NORMAL < 7/30 target occurrences → **INCONCLUSIVE**, never "no leak" and never "fixed".

**Outcome labels:**
- **ROOT_CAUSE_PROVEN:** RC1, RC2, RC3, RC5, RC6 and RC7 met. RC4 is reported either way.
- **ROOT_CAUSE_PARTIAL:** ownership is established (RC1–RC3) but linkage, retention or completeness is not.
- **MULTIPLE_CAUSES:** more than one signature, or an ACCUMULATING_RETENTION finding.
- **INCONCLUSIVE:** insufficient reproduction or attribution. Stage D is INCOMPLETE.
