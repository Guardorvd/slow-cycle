### 2.1. Значение статусов

- **CURRENT:** действует в явно указанной области; не означает подтверждённый runtime PASS.
- **HISTORICAL:** датированный снимок, отчёт или evidence; не задаёт текущую цель/следующую задачу.
- **SUPERSEDED:** прежняя нормативная роль заменена названным новым источником; технические сведения сохраняются.
- **CONTRADICTORY:** содержит действующие на вид указания, расходящиеся с Blueprint/Master либо с более поздним состоянием. Полезные части не обесцениваются автоматически.
- **REDUNDANT:** повторяет уже принадлежащую другому источнику текущую информацию; уникальные исторические сведения сохраняются.

Таблица даёт один основной статус **до D0**. Колонка «После D0» задаёт предлагаемую роль; статус документа не переклассифицирует тесты, не отменяет assertions и не подтверждает завершение фазы.

## 4. Hierarchy источников истины

Это распределение полномочий по области, а не право нижестоящего документа менять вышестоящий.

1. **Текущие явные решения пользователя**, включая запрет реализации без согласования и D0 scope.
2. **`docs/TARGET_GAME_BLUEPRINT.md`** — что строим: продукт, свобода, region-first, topology, anti-scope, human acceptance.
3. **`docs/MASTER_IMPLEMENTATION_PLAN.md`** — как и в каком порядке переходим, KEEP/ADAPT/REPLACE, фазы и общие инженерные границы. Описания стратегии читаются в пределах Blueprint.
4. **Производные current документы:** `docs/TARGET_ARCHITECTURE.md` — целевые владельцы/потоки; `docs/LEGACY_MIGRATION_MATRIX.md` — судьба старых систем; `docs/TEST_STRATEGY.md` — стратегия доказательств. Они ссылаются на первоисточники, не создают конкурирующих целей, численных бюджетов или разрешений менять тесты.
5. **Рабочие правила и scope:** `AGENTS.md` регулирует процесс и защиту систем; `implementation_plan.md` содержит один task plan с явным approval status. Ни roadmap, ни наличие файла, ни прошлое approval не разрешают следующую фазу. `.antigravity/rules/test-integrity.md` продолжает защищать существующие assertions; его противоречащая продуктовой authority формулировка зарегистрирована и не используется для возврата к road-first цели.
6. **As-is/evidence:** `ARCHITECTURE.md`, `docs/CURRENT_PROJECT_STATE.md` и read-only код описывают фактическую реализацию/миграционные риски. Отчёты доказывают только своё покрытие на своей ревизии. `README.md`, `VISION.md`, `docs/README.md` — навигация/краткие производные, не дополнительные независимые authorities.
7. **История:** SUPERSEDED/HISTORICAL документы, `docs/history/`, `docs/plans/history/`, `docs/plans/completed/`, `docs/sprints/`. Не дают текущих next tasks и не вводят продуктовых запретов.

`docs/DECISIONS/` хранит traceability решений и область их действия. D0-решение фиксирует только уже заданную authority и архивирование. Изменить Blueprint/Master через незаметный ADR нельзя: расхождение с ними требует отдельного решения пользователя и отдельного scope.

При неразрешённом конфликте двух current нормативных источников записать точные утверждения, не выбирать молча одно и не менять код. Существующий runtime определяет безопасный маршрут миграции, но не получает право отменить region-first цель.

## 7. Сохранение истории и полезной техники

История хранится двумя способами: сохранённые файлы на прежних путях с historical/superseded статусом и snapshots только четырёх содержательно заменяемых документов плюс прежнего implementation journal. Не удалять старые roadmaps, тестовые команды, таблицы contracts, defect IDs, metrics, formulas, logs/capture paths и ограничения.

Для четырёх Markdown snapshots разрешены добавление historical header и **только** переназначение относительных ссылок под новый каталог. Все исходные разделы и числа сохраняются; оригинальный текст проверяется сравнением с `ed7d132`. Записать source path/revision и исходный SHA256 в history index; SHA256 архивной копии может отличаться только из-за перечисленных header/link edits.

Raw `IMPLEMENTATION_PLAN_PRE_D0_ed7d132.md` сохраняется байт-в-байт. Его прежние relative ссылки имеют исходную базу `/implementation_plan.md`, а не новый каталог. `docs/plans/history/README.md` содержит resolution map этих ссылок и live ссылки на retained reports/reference; raw snapshot исключается из проверки *перемещённых* относительных ссылок, проверяется с original base. Исключение только для этого конкретного raw файла, с hash и объяснением, не для всей истории.

У каждой старой содержательной части должна быть судьба: сохранена на месте, в названном snapshot либо отражена в current as-is с ссылкой на оригинал. `docs/DOCUMENTATION_AUDIT.md` и history index обеспечивают эту traceability. Будущие незавершённые P/B/WORLD предложения не превращаются в completed tasks из-за переноса истории.
