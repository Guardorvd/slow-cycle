# Generator V2 — план GEN2 (компактный)

STATUS: GEN2-1 COMPLETE — Директор принял результат 2026-10-16 («все норм»), ветка `gen2-1-trail-tool`, PR в master на его проверку; GEN2-2…GEN2-5 — PROPOSED, каждый ждёт отдельного «да». Обоснования и числа: [GENERATOR_V2_REPORT.md](GENERATOR_V2_REPORT.md) (ревизия 2). Этапы V2-0…V2-3 из ревизии 1 отменены; действует только нумерация GEN2-1…GEN2-5.

Цель: разные по устройству горы и долины, разные по характеру маршруты, удобная реальная езда на текущем велосипеде, короткий цикл «изменил → сгенерировал → проехал». Физика, камера и управление не меняются.

Порядок — по решению Директора (G1). Две уточнённые зависимости: точному режиму инструмента (GEN2-1/2) нужна публикация только затронутых тайлов в dev-кэш, поэтому её простая версия появляется уже в GEN2-1, а полная пересборка компонент с кэшем — в GEN2-3; первому спуску нужна локальная оценка склона (уклон вдоль/поперёк, перепад, доступ), это частный случай карты возможностей GEN2-4.

Каждый этап — отдельная ветка и спринт-карта; проверка = FAST (≈10–15 с) + пакет PLAYTEST (3–5 снимков, чистый лог, команда запуска), закрытие этапа — после езды Директора. DEEP только по решению Директора. Каждый этап требует отдельного «да» перед стартом.

## GEN2-1. Инструмент одной тропы + замер стоимости стадий + снимок V1

- **Результат для игры:** «поменял параметр → через секунды вижу тропу сверху → через минуту еду по ней».
- **Минимальный объём:**
  - снимок V1 (отчёт §10): локальный тег `generator-v1` на `d2ad73f`, архив кэшей 184729/3628391/2024 (Linux), сводки bake с дайджестами, описание среды; Windows-кэши — если Директор запустит bake у себя (через Remote Control);
  - `tools/dev/trail_probe.gd`: вход — сид, регион, точка/зона, параметры тропы; режим **preview** (линия, профиль скорости, операции на растре, PNG сверху) и режим **exact** (публикация затронутых тайлов в dev-кэш поверх кэша V1, проверка, команда запуска в точке тропы);
  - счётчики и таймеры стадии троп: подготовка растра, планирование, операции, уточнение, швы, финал, граф, повторные публикации; одна сводка на прогон.
- **Зависимости:** нет (работает на кэше V1).
- **Проверка:** один холодный bake 184729 с таймерами (это и есть замер); preview и exact одной существующей тропы V1 дают тот же дайджест тайлов, что полный bake; FAST — парс + тест инструмента.
- **Риски:** публикация части тайлов может разойтись со швами полного мира → сравнение дайджестов обязательно; размер архива V1 не измерен.
- **Уточнения Директора (2026-10-16):** снимок V1 локально, вне Git, без автоматической публикации; отсутствие кэшей сидов не блокирует инструмент; preview и exact с разными критериями; дайджесты exact сравниваются с полной публикацией того же набора троп на той же земле, плюс неизменность тайлов вне зоны зависимостей; сначала существующий механизм публикации, расширение — только с объяснённой зависимостью; один холодный bake 184729 с таймерами; цели 10/60 с — рабочие, не обещание; проверки успеха на подходящих примерах и объяснённого отказа на неподходящих.
- **Итог (сводка; подробно — [docs/investigations/GEN2_1.md](../investigations/GEN2_1.md) и папка [gen2-1/](gen2-1/)):**
  - снимок V1: локальная папка проекта `generator-v1-snapshot/`, описание — [V1_SNAPSHOT.md](V1_SNAPSHOT.md) (111 МБ, архивы в Git не входят: код `d2ad73f`, кэши 184729, 3628391, 2024 с Linux, сводки, среда, инструкция); 184729 совпал с историческими дайджестами; на 2024 воспроизвёлся дефект N-7;

  - замер: холодный bake 184729 597 с (V1 533 с, разброс между прогонами ~12 %); стадия троп 101 с, из них уточнение тайлов 73.5 с, планировщик 16.3 с; preview 24 с в новом процессе (из них ~11.7 с — перестройка деформера R7 при загрузке), 3–5.5 с на тропу внутри процесса; exact 65 с в новом процессе (тропа на 1 тайле), 36–82 с внутри процесса; цели 10/60 с в новом процессе не достигнуты;

## GEN2-2. Одна полная горная петля: подъём + серпантинный спуск (первый чекпойнт)

- **Результат для игры:** на 184729 от дороги долины тропа поднимается на склон и серпантином спускается обратно к дороге; по ней удобно ехать без телепортов и ловушек.
- **Минимальный объём:**
  - `TrailLineBuilder` способом C (отчёт §4): конструктивная раскладка ног по грани + короткий поиск с курсом между якорями + параметрические развороты (плоская площадка / профилированный разворот); линия из отрезков, дуг и переходов, без свободного Catmull-Rom;
  - профиль скорости (торможение до разворота, разгон, обзор) и проверка удобства манёвра (отчёт §6), а не только радиус;
  - операции земли с единым правилом композиции (отчёт §3.5): приоритеты, веса, откат по тропе, локальная перепроверка, исключение растительности по следу;
  - локальная оценка склона (уклон вдоль/поперёк, перепад, расстояние до дороги);
  - три исхода отказа: геометрически невозможно / превышен бюджет земли / нежелательный вид — каждый с причиной в сводке;
  - Input-замер разворотов R 4 / 4.5 / 5 / 6 м на текущем велосипеде (без изменения физики) — проверка гипотезы о минимальном радиусе.
- **Зависимости:** GEN2-1. Сеть, развилки и новая география не входят.
- **Проверка:** FAST — тесты «поворот и скорость» и «крутой склон» (ниже); exact-публикация; PLAYTEST — снимки верхней точки, двух разворотов, стыка с дорогой, вида сверху; команда запуска у начала петли.
- **Риски:** гипотезы радиуса и бюджетов земли могут не подтвердиться в езде → тогда меняются числа политики, а не физика; на 184729 склон может не вместить нужную длину → запасной вариант: спуск 90–107 м от дороги к дороге на 3628391.
- **Данные для выбора склона (GEN2-1, `trail_probe --mode=slopes`, 184729):** кандидаты вершин по полосам перепада над ближайшей дорогой, с прямой «дорога → вершина» (перепад, длина, уклон между концами, средний и наибольший |∇h| вдоль прямой, вода) и оценкой длины тропы (подъём 6 %, спуск 10 %). Южные холмы долины: перепад ~120 м на 0.7–0.9 км, средний |∇h| 0.22–0.64 (подъём ≈ 2.0 км, спуск ≈ 1.2 км по оценке). Северный склон: перепад 270–330 м на ~1.5 км, средний |∇h| 0.49–0.66 (спуск ≈ 2.7–3.3 км по оценке). Это данные для выбора, а не проверка выполнимости: петля заявляется выполнимой только после построения и exact-проверки.

## GEN2-3. Быстрая публикация + дороги без природных классов

- **Результат для игры:** изменение одной тропы публикуется за секунды-десятки секунд, холодная генерация региона не медленнее V1.
- **Минимальный объём:** публикация по тайлам с ключом (исходные массивы + пересекающие операции + вынужденные точки шва), пересборка затронутой компоненты, отказ одной тропы не трогает сеть; R5/R6 строят только дороги (природные раунды и `SINGLETRACK`/`TECHNICAL` в R6 убираются, тропы — только из V2).
- **Зависимости:** GEN2-2 (формат операций).
- **Проверка:** дайджест частичной публикации = полной; один холодный bake 184729 (время, память) против замера GEN2-1; FAST — тест швов тайлов.
- **Риски:** перекат дорожных сетей всех сидов (разрешено G2); растёт сложность кэша → ключи только по реальным зависимостям.

## GEN2-4. Разнообразная география + карта возможностей + доступ

- **Результат для игры:** сиды дают разные по устройству рельефы (не одна речная долина); дороги подводят к верхним зонам там, где есть хорошие спуски.
- **Минимальный объём:** граф элементов R1 (сеть долин, несколько хребтов, врезы, плато/котловины, шаблоны) в GDScript и C#-ядре с паритетом; гидрология с магистралью для всех шаблонов; `RideOpportunityMap` (чистый растр) до финальной раскладки дорог; до K якорей `RIDE_ACCESS` в R5 с ограниченной стоимостью, без перепланирования.
- **Зависимости:** GEN2-3 (дороги без природных классов).
- **Проверка:** FAST — паритет ядра на новых примитивах, тест «несколько географий» (каждый шаблон: связная магистраль дорог, вода, возможности > 0); один bake на новом шаблоне; PLAYTEST — снимки 2–3 разных шаблонов.
- **Риски:** новые примитивы ломают паритет/время bake → только в C#-ядре с тестом; доступ может удорожить R5 → лимит по счётчику.
- **C# и эталон (обоснование, уточнение Директора):** рабочий оценщик — C#-ядро (в 12 раз быстрее на отсчёт, PERF_FIRST), им пользуется сборка Директора. Эталон для новых примитивов — описание в GDScript (читаемое, работает в стандартной сборке и в облаке). Это две разные проверки: (1) **воспроизводимость** — в одной среде (сборка, ядро, ОС) тот же сид даёт те же дайджесты; (2) **численное соответствие** двух реализаций — разность высот в пределах допуска (предлагаю |Δh| ≤ 1 мм на контрольных точках), а не побитовое совпадение. Существующее ядро сейчас проверяется побитово (`kernel_parity.gd`, 0 расхождений) — это остаётся как есть; для новых примитивов побитовость не вводится автоматически. Следствие: продукты стандартной и .NET-сборки могут отличаться в последних битах; каждая среда воспроизводима сама по себе.

## GEN2-5. Сеть: развилки, петли, альтернативы, возврат

- **Результат для игры:** от одной точки несколько вариантов — спокойный и технический, петли, развилки, понятный возврат.
- **Минимальный объём:** развилки/слияния троп, пересечения дорог в уровень, броды (по итоговому руслу и подходам), выбор по вектору характера и по тому, чего в сети не хватает; сложность по самому трудному обязательному элементу; проверка возврата; удаление кода и тестов V1 по явному списку на утверждение.
- **Зависимости:** GEN2-2…GEN2-4.
- **Проверка:** FAST — тесты соединений и возврата; одна сводка сети на 184729; PLAYTEST — развилка, брод, пересечение, петля.
- **Риски:** конфликт операций в развилках → правило композиции и откат по тропе; объём удаления V1 — отдельное утверждение.

## Набор проверок (небольшой, со смыслом)

1. **Поворот и скорость:** каждый разворот проходим по профилю скорости с запасом (торможение, обзор, вход/выход), отказ — с причиной.
2. **Крутой склон:** на 45 % и 70 % — либо тропа, либо классифицированный отказ (невозможно / бюджет / вид), без молчаливых пропусков.
3. **Наложение операций:** развороты, площадки, ноги рядом — земля непрерывна, без ступенек и дыр.
4. **Швы тайлов:** видимая поверхность = коллизия, без щелей на границах тайлов.
5. **Соединения:** тропа ↔ дорога и тропа ↔ тропа сходятся в пределах допуска; мост — не соединение; брод — по итоговому руслу.
6. **Возврат:** из каждого конца есть путь обратно к дорожной сети с учётом подъёма и обязательной сложности.
7. **Воспроизводимость:** тот же сид → те же дайджесты; частичная публикация = полной.
8. **Несколько географий:** каждый шаблон проходит базовые проверки (с GEN2-4).

Нет тестов вида «≥ 3 серпантина» или «≥ N троп»: проверяется качество того, что построено.
