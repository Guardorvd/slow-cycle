# Перестройка конвейера с R5 — сверка рекомендации с кодом и замерами

2026-10-17. Это сверка, а не план. Код и репозиторий не менялись. Все числа взяты из холодного bake 184729 в GEN2-1 (`gen2-1/cold_bake_184729_timed.json`, Linux, 4 потока, одна сборка) и из check-режима (`gen2-1/check_184729_summary.json`). Каждый замер выполнен один раз.

## 3. С чем согласен и где нужна осторожность

**Согласен:**
- Основная поверхность должна храниться как данные высот блоками. Мосты уже сделаны отдельными объектами.
- Дороги и тропы должны стать одной системой операций над землёй. Это то же правило композиции, которое стоит в GEN2-2.
- Граф возможностей до R5 совпадает с `RideOpportunityMap` из GEN2-4.
- Первой проверкой нового подхода стоит сделать небольшой законченный участок.

**Осторожно:**
1. **Тип покрытия по точке контакта требует изменить велосипед.** Это защищённая система (AGENTS.md): нужна отдельная задача по велосипеду с измеренным дефектом и отдельным утверждённым планом. Параметры движения при этом не меняются, меняется только способ узнать покрытие. Есть обходной путь без правки велосипеда: оставить полосу тропы отдельным тонким коллайдером на своём слое. Его риск — ступеньки на стыке, поэтому я его не рекомендую.
2. **Разрешение карты высот.** Узкая тропа (1–1.5 м) и профилированный разворот требуют шага сетки не больше 0.5 м там, где они проходят. Сплошная сетка с таким шагом на весь регион слишком дорога. Нужны блоки разной детализации с согласованными швами. `HeightMapShape3D` задаёт одну равномерную сетку на форму, поэтому коллизию придётся собирать блоками.
3. **Terrain3D** — внешнее расширение (GDExtension). Не проверено: совместимость с Godot 4.7.2 Mono и headless bake на Linux, воспроизводимость, шаг коллизии под узкую тропу. Его стоит проверить в коротком сравнительном опыте, но не брать основой заранее.
4. **«Заменить связку R5–публикация» одним шагом опасно.** Это перестройка всего сразу, и в ней ломаются старые тесты и G-гейты. Лучше вести её по этапам, начиная с одного законченного участка, как и предлагает сама рекомендация.

## 4. Что меняется в плане GEN2

- **GEN2-2** (петля на 184729) сейчас строится на старой публикации, которую предлагается заменить. Предлагаю поставить первым **прототип участка на новой поверхности** на земле 184729 размером 1–2 блока. В него входят:
  - блоки высот;
  - единые операции: профиль дороги, NATURAL как след и покрытие, SHAPED-разворот;
  - коллизия `HeightMapShape3D` по блокам;
  - растительность в два шага: кандидаты по природным полям, затем посадка на итоговую землю;
  - замеры: время блока, время до старта езды, сравнение с текущими 12–17 с на тайл.

  Петля переходит на этот прототип следующим шагом.
- **GEN2-3** (быстрая публикация по тайлам) почти целиком становится частью блочной поверхности: обновление по блокам получается само собой.
- **GEN2-4** дополняется ограниченным набором конструкций R6 (след, траверс, дорожный профиль, полка, разворот, примыкание, мост). Поиск выполняется только для выбранных коридоров, без повторного R5 после отказа.
- Это архитектурное изменение, поэтому нужен новый компактный ExecPlan и утверждение. Отдельное решение требуется по задаче велосипеда (п. 3.1) и по опыту с Terrain3D.

Коэффициент ускорения неизвестен, пока нет прототипа и сравнительного запуска.
